# Добавление продуктов списком и голосом

Работает без серверного ключа: ввод русского списка, количества и единицы, диктовка через браузер, редактирование распознанных строк, подтверждение и атомарное сохранение. Неизвестные названия и неоднозначные количества требуют проверки. Дубли не увеличивают запасы и не перезаписывают уже сохранённые продукты.

Это локальный разбор правил, а не работающая языковая модель. Интерфейс честно показывает «Разбор на устройстве».

Голос запускается только кнопкой пользователя, заканчивается не позднее 45 секунд плюс ожидание финального фрагмента до 2 секунд. При уходе со страницы распознавание прерывается. Поддержка зависит от браузера; есть обычный текстовый ввод. Аудио может обрабатывать сервис браузера — это указано до запуска микрофона. Живой звук в QA не записывался; lifecycle и результаты Web Speech API покрыты mock-тестами.

## ИИ-подключение

Подготовлены клиентский адаптер и отдельный серверный Worker `server/fridge-assistant.ts`. Он ещё **не развёрнут**, действующий ключ **не создан**: автоматическая проверка запросила отдельное прямое разрешение пользователя на бессрочный ключ.

После разрешения и успешной выдачи ключа нужны серверные `OPENAI_API_KEY`, `OPENAI_MODEL`, D1 binding `DB` с миграцией из `server/migrations` и origin Cookly. На клиенте задаётся только публичный `VITE_FRIDGE_ASSISTANT_URL`; секрет никогда не передаётся в Vite/GitHub Pages. Сервер собирается отдельно командой `npm run build:assistant`.

Ограничения сервера: 3 запроса в минуту и 20 в сутки на IP, 200 в сутки суммарно; счётчики сохраняются между инстансами. При отсутствии ключа, модели или БД запрос закрывается с 503. Пользовательский текст и результат не сохраняются в БД, upstream вызывается с `store: false`. Ответ модели строго проверяется и всегда проходит тот же экран подтверждения. Свободные вопросы и произвольный выбор модели клиентом не поддерживаются.

## Проверка

Production build проходит. В браузере проверены разбор количества, ручное исправление, блокировка отрицательных значений, дубли, подтверждение, сохранение после перезагрузки и ширина 320 px. Backend проверяется без реальных платных вызовов.

Распознавание продуктов по фото и обновление дизайна остаются следующими этапами.

Документация: [Web Speech API](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition), [структурированный ответ OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).
