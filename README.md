# COOKLY

Cookly помогает решить, что приготовить из продуктов, которые уже есть дома. Добавьте продукты, при желании ограничьте время и получите до пяти подходящих блюд с подробными рецептами. В каталоге — 48 домашних рецептов на русском языке.

Это статический MVP на React, TypeScript, Vite и React Router. Для работы не нужны аккаунт, сервер, база данных, API-ключи или AI API.

## Локальный запуск

Понадобятся Node.js **22.12 или новее**, npm и Git. Все команды выполняются в папке проекта.

```sh
npm install
npm run dev
```

Откройте адрес, который покажет Vite в терминале, обычно `http://localhost:5173`. Остановить сервер можно сочетанием `Ctrl+C`.

```sh
# Проверить логику приложения
npm run test

# Проверить TypeScript и собрать production-версию
npm run build

# Посмотреть собранный сайт локально
npm run preview
```

Готовые файлы находятся в `dist/`. Сервер preview обычно доступен по адресу `http://localhost:4173`; он предназначен для локальной проверки сборки. В CI используется `npm ci`, поэтому `package-lock.json` нужно хранить в Git вместе с `package.json`.

## Что реализовано

- Ввод продуктов с клавиатуры, быстрые подсказки, удаление и очистка списка, защита от повторов.
- Необязательный лимит времени: 20, 30, 45 или 60 минут.
- Подбор блюд по составу; карточки показывают совпадения и недостающие продукты.
- Подробный рецепт с количеством ингредиентов, порциями и шагами приготовления.
- Подтверждение «Буду готовить», состояние загрузки и понятные пустые состояния.
- Адаптивная верстка для телефона и компьютера, видимый фокус и доступные элементы управления.
- Восстановление продуктов и выбранного времени из localStorage.
- Локальная аналитика основных действий без отдельного пользовательского dashboard.
- SVG-логотип, локальные данные и подготовленный workflow GitHub Pages.
- Профиль семьи без регистрации: размер семьи, дети, нелюбимые продукты, аллергии, тип питания и сложность.
- Умные замены отсутствующих продуктов с подсветкой варианта, который уже есть дома.
- Пересчёт ингредиентов на 1–6 порций с округлением штучных продуктов вверх.
- Cooking Mode с текущим шагом, таймером, навигацией назад/вперёд и полным списком шагов.
- Финальная оценка блюда 👍/👎 с сохранением в localStorage и влиянием на следующие рекомендации.

## Структура проекта

```text
src/
  components/       Повторно используемые элементы интерфейса
  pages/            Главная, рекомендации и страница рецепта
  data/             Каталог рецептов и справочник продуктов
  types/            Типы рецептов, ингредиентов и рекомендаций
  utils/            Нормализация, подбор и аналитика
  hooks/            Состояние продуктов, профиля и отзывов
  App.tsx           Маршруты приложения
public/             Статические файлы
.github/workflows/
  deploy.yml        Проверка, сборка и публикация в GitHub Pages
```

Данные, подбор и аналитика отделены от UI: можно расширять каталог или менять способ записи событий без переписывания экранов. `useProfile` хранит настройки семьи, `substitutions.ts` содержит логичные пары замен, `servings.ts` отвечает за масштабирование количеств, а Cooking Mode управляет пошаговой готовкой.

## Как работает подбор

Названия продуктов нормализуются: регистр, пробелы и распространенные варианты названий не должны создавать разные продукты. Для каждого рецепта определяется наличие ингредиентов и рассчитывается взвешенная доля совпадений. Основные продукты имеют больший вес, чем вспомогательные.

В первую очередь предлагаются блюда, для которых есть все обязательные продукты, затем блюда с одним и двумя недостающими продуктами. Остальные варианты дополняют выдачу при необходимости. Учитывается выбранное ограничение времени; случайного перемешивания нет. Если подходящих блюд мало, приложение показывает доступное количество, а не добавляет рецепты вне лимита.

Соль, перец, вода, масло и базовые специи считаются запасами кухни: их не требуется вводить. Это допущение MVP, а не проверка фактического наличия продуктов. Необязательные ингредиенты не должны мешать рекомендации блюда.

## Сохранение данных и аналитика

Данные сохраняются только в текущем браузере:

| Ключ localStorage | Содержимое |
| --- | --- |
| `cookly:pantry` | Последний список продуктов |
| `cookly:time` | Выбранный лимит времени |
| `cookly:analytics` | События с временными метками |

Утилита `analytics.ts` регистрирует `ingredient_added`, `recommendations_requested`, `recommendations_shown`, `recipe_opened`, `cook_confirmed`, `profile_updated`, `servings_selected`, `ingredient_substitution_viewed`, `cooking_started`, `cooking_step_changed`, `cooking_completed`, `recipe_liked` и `recipe_disliked`. В режиме разработки события можно проверять в консоли. Для просмотра сохраненных событий в DevTools:

```js
JSON.parse(localStorage.getItem('cookly:analytics') || '[]')
```

Эта аналитика проверяет сценарий на конкретном устройстве. Она не собирает общую статистику посетителей и не отправляет события владельцу сайта. В дальнейшем реализацию утилиты можно заменить интеграцией с PostHog или Google Analytics, согласовав сбор данных с пользователями. Очистка данных сайта в браузере удалит сохраненный список и события.

Профиль сохраняется под ключом `cookly:profile`, выбранное количество порций рецепта — под `cookly:servings:<recipeId>`, отзывы — под `cookly:feedback`. Аллергии исключают несовместимые рецепты; нелюбимые продукты снижают их приоритет. Положительные и отрицательные оценки корректируют будущую сортировку.

## Публикация в GitHub Pages

### 1. Создайте репозиторий

В GitHub выберите **New repository**, задайте имя, например `cookly`, и создайте пустой публичный репозиторий. Не добавляйте README, `.gitignore` или лицензию на этом шаге: файлы проекта уже находятся локально. Публичный репозиторий позволяет пользоваться GitHub Pages на бесплатном тарифе.

### 2. Включите GitHub Pages

Откройте репозиторий → **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**. Сборка будет выполняться workflow, а результатом публикации станет содержимое `dist/`. Этот способ описан в [документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

### 3. Загрузите проект

Замените `OWNER` на ваш логин или организацию, а `cookly` — на фактическое имя репозитория:

```sh
git init
git add .
git commit -m "Create Cookly MVP"
git branch -M main
git remote add origin https://github.com/OWNER/cookly.git
git push -u origin main
```

Если `origin` уже настроен, проверьте его командой `git remote -v` и при необходимости замените адрес через `git remote set-url origin https://github.com/OWNER/cookly.git`. Для push потребуется ваша обычная авторизация в GitHub.

### 4. Дождитесь workflow

Во вкладке **Actions** откройте **Deploy Cookly to GitHub Pages**. Workflow запускается после push в `main` и вручную через **Run workflow**:

1. Получает код и настраивает Node.js 22.
2. Устанавливает зависимости командой `npm ci`.
3. Выполняет тесты и production-сборку.
4. Передает `dist/` в GitHub Pages и публикует сайт.

В файле workflow уже заданы разрешения `contents: read`, `pages: write`, `id-token: write`, окружение `github-pages` и последовательное выполнение публикаций через `concurrency`. Дополнительные секреты не нужны. Если организация ограничивает GitHub Actions, ее политика должна разрешать используемые официальные actions. Если первый запуск произошел до включения Pages, после настройки повторите его.

### 5. Откройте сайт

После успешной публикации URL появится в **Settings → Pages** и в результате deploy job. Для обычного репозитория `cookly` адрес будет:

```text
https://OWNER.github.io/cookly/
```

Для специального репозитория `OWNER.github.io` адрес будет `https://OWNER.github.io/`. Фактическая публикация произойдет только после загрузки проекта в ваш репозиторий и успешного выполнения workflow.

### Base path и прямые ссылки

Workflow автоматически передает `VITE_BASE_PATH`: `/cookly/` для проекта `cookly`, `/` для репозитория `OWNER.github.io`. Vite читает переменную через `loadEnv` и использует `base: env.VITE_BASE_PATH || './'`; локальная сборка по умолчанию получает относительные пути. Правила для project sites и корневых сайтов описаны в [документации Vite](https://vite.dev/guide/static-deploy.html#github-pages).

Используется `HashRouter`: путь экрана находится после `#`. Поэтому обновление страницы рецепта и открытие скопированной ссылки работают на статическом хостинге без серверной настройки маршрутов. Удалять `#` из ссылки не нужно.

Для проверки сборки с путем проекта в PowerShell:

```powershell
$env:VITE_BASE_PATH = '/cookly/'
npm run build
npm run preview
```

Откройте `http://localhost:4173/cookly/`. После проверки можно удалить переменную командой `Remove-Item Env:VITE_BASE_PATH`. Если подключите собственный домен в корне, задайте `VITE_BASE_PATH: /` в workflow.

## Ручная проверка сценария

1. Добавьте курицу, картофель, лук, помидоры и сыр; оставьте время «Неважно».
2. Убедитесь, что повторный ввод продукта не создает дубликат.
3. Нажмите «Что приготовить?» и дождитесь результатов; должно быть минимум три релевантных блюда.
4. Откройте рецепт, проверьте наличие количества ингредиентов, разделения на доступные и недостающие продукты и подробных шагов.
5. Нажмите «Буду готовить» и проверьте подтверждение.
6. Вернитесь к продуктам и обновите страницу: список должен восстановиться.
7. Проверьте пустой список, очень короткий лимит времени, удаление и очистку продуктов.
8. Повторите на ширине 320–430 px и на широком экране; проверьте отсутствие горизонтального скролла и работу клавиатуры.
